# แบบระบบ: TTS ภาษาไทยสำเนียงญี่ปุ่น เสียงสาวน้อยสไตล์ VTuber

วันที่: 2026-11-13
อ้างอิง: รายงาน `reports/TTS ไทยสำเนียงญี่ปุ่น.md` (ตารางกฎแปลง phoneme 33 ข้อ และ pipeline ที่แนะนำ)

## 1. เจตนาและเหตุผล

ผู้ใช้ต้องการ **ทดลองการเทรนโมเดลเสียงด้วยตัวเอง** โดยมีโจทย์เป็นระบบที่รับข้อความภาษาไทย แล้วพูดออกมาเป็นภาษาไทยสำเนียงญี่ปุ่นด้วยเสียงสาวน้อยแบบ VTuber
ส่วนที่เทรนเองคือ **acoustic model เสียงสาวญี่ปุ่น** (ผู้ใช้เลือก) ส่วนสำเนียงมาจากตัวแปลงตามกฎ ที่เปลี่ยนภาษาไทยให้เป็น phoneme ญี่ปุ่นก่อนเข้าโมเดล

แนวคิดหลัก: โมเดลถูกเทรนด้วยเสียงญี่ปุ่นล้วน จึงรู้จักเฉพาะหน่วยเสียงญี่ปุ่น เมื่อป้อน "ภาษาไทยที่ถอดเป็น mora ญี่ปุ่น" เข้าไป สำเนียงญี่ปุ่นจะเกิดขึ้นเองโดยธรรมชาติ ซึ่งเป็นแนวเดียวกับงาน rule-based accent TTS (arXiv 2603.07550) และ MacST (arXiv 2409.09352) ในรายงาน

## 2. เป้าหมาย / สิ่งที่ไม่ทำ / สิ่งที่ถือว่าล้มเหลว

**เป้าหมาย**
- ผู้ใช้ได้ผ่านวงจรการเทรนครบ ได้แก่ เตรียมข้อมูล → fine-tune → resume บน Colab → ประเมินผล → ปรับแล้วเทรนซ้ำ
- ได้เสียงสาวน้อยที่คนไทยฟังรู้เรื่อง และได้ยินชัดว่าเป็นสำเนียงญี่ปุ่น
- ปรับความเข้มของสำเนียงได้ 3 ระดับ (เบา/กลาง/เข้ม) โดยนิยามใหม่ให้อยู่ภายในชุดหน่วยเสียงญี่ปุ่น (ดูข้อ 5.2)

**สิ่งที่ไม่ทำ**
- ไม่ทำ real-time หรือ live streaming (ทำแบบ batch สังเคราะห์ทีละประโยคก็พอ)
- ไม่ตั้งเป้าว่าวรรณยุกต์ไทยต้องถูกครบ 5 เสียง (ความเพี้ยนเป็นส่วนหนึ่งของสำเนียง)
- ไม่เทรน acoustic model ภาษาไทย และไม่เทรน G2P

**สิ่งที่ถือว่าล้มเหลวแม้ระบบจะทำงานได้**
- โคลนเสียงของ VTuber หรือนักพากย์ที่มีตัวตนจริงโดยไม่ได้รับอนุญาต
- สำเนียงเข้มจนคนไทยฟังไม่ออก (ระดับ "เบา" ต้องฟังรู้เรื่องเสมอ)
- ใช้ข้อมูลเสียงที่เงื่อนไขการใช้ไม่อนุญาตให้เทรนโมเดล

## 5. สถาปัตยกรรม

```
ข้อความไทย
  │
  ▼
[1] Thai front-end
    PyThaiNLP ตัดคำ → umt5-thai-g2p → IPA + วรรณยุกต์ → แยกพยางค์
  │
  ▼
[2] Accent rule engine  (level = light | medium | strong)
    ใช้กฎจากตารางในรายงาน ([E] / [E+I] / [I])
  │
  ▼
[3] Mora mapper
    พยางค์ → mora ญี่ปุ่น (ชุด phoneme เดียวกับ SBV2 JP / pyopenjtalk)
    วรรณยุกต์ → tone 0/1 ต่อ mora
  │
  ▼
[4] SBV2 JP-Extra (โมเดลที่ fine-tune เอง)
    รับ phones + tones ตรง ไม่ผ่าน g2p ญี่ปุ่นของตัวโมเดล
  │
  ▼
WAV เสียงสาวน้อยสำเนียงญี่ปุ่น
```

### 5.1 Thai front-end
- ตัดคำด้วย PyThaiNLP แล้วแปลงเป็น IPA และวรรณยุกต์ด้วย `B-K/umt5-thai-g2p` (Apache-2.0, CER 0.094)
- ผลลัพธ์ที่ได้: รายการพยางค์ แต่ละพยางค์มีฟิลด์ `{onset, cluster, vowel, length, coda, tone}`
- ต้องมีพจนานุกรมแก้คำ (override) สำหรับคำที่ G2P อ่านผิด เพราะรายงานชี้ว่าคุณภาพ front-end ส่งผลต่อ WER มาก

### 5.2 Accent rule engine
- นำตารางกฎ 33 ข้อในรายงานมาเขียนเป็นข้อมูล (YAML) แต่ละกฎระบุ id, เงื่อนไข, ผลลัพธ์, ระดับที่เริ่มใช้ และแท็กหลักฐาน
- **ระดับของแต่ละกฎใช้ตามคอลัมน์ "ระดับ" ในตารางของรายงาน** ไม่ได้ใช้แท็กหลักฐาน (การตัดสินใจของผม)
- **ข้อจำกัดที่ต้องรู้ไว้ (การตัดสินใจของผม):** โมเดลถูกเทรนด้วยเสียงญี่ปุ่นล้วน จึงไม่มีเสียงที่ภาษาญี่ปุ่นไม่มี ได้แก่ เสียงพ่นลมที่ตัดกับไม่พ่นลม, /l/ แยกจาก /r/, คำควบโดยไม่เติมสระ, ɛ/ɔ/ɤ และตัวสะกด -p/-t/-k แบบไม่ปล่อยลม
  - ผลคือกฎบางข้อในระดับกลางและเข้มจะ "ถูกใช้โดยปริยาย" ทุกระดับ เช่น กฎ 3, 9, 20, 22
  - **ระดับจึงนิยามใหม่ว่าเป็น "ความเข้มภายในชุดหน่วยเสียงญี่ปุ่น"**
    - **เบา:** ใช้ mora ที่ใกล้ไทยที่สุด ไม่เติมสระในคำควบ (ใช้ `kur` แบบ devoice สั้นที่สุดเท่าที่ SBV2 ทำได้) ตัวสะกดหยุดเป็น `q`
    - **เข้ม:** ใช้กฎแบบคาตาคานะเต็มรูป เช่น เติมสระท้าย, -m → ム, ɤ → ウ/オ
  - เกณฑ์ "ระดับเบาต้องฟังรู้เรื่อง" ยังใช้อยู่ ถ้า M0 แสดงว่าทำไม่ได้ จะกลับมาคุยกันใหม่ (ดูข้อ 6)
  - การเพิ่มสัญลักษณ์เสียงไทยเข้าไปในโมเดลไม่อยู่ในขอบเขต เพราะไม่มีเสียงไทยให้โมเดลเรียนรู้ embedding เหล่านั้น
- ทำงานแบบ deterministic ใส่ประโยคเดิมต้องได้ผลเดิม และบันทึก log ว่ากฎใดถูกใช้กับพยางค์ใด เพื่อใช้วิเคราะห์ตอนประเมินผล

### 5.2b กฎด้านจังหวะและ pitch (การตัดสินใจของผม)
- **อยู่ในขอบเขต (ทำได้โดยไม่ต้องแก้โค้ดภายในโมเดล):**
  - กฎ 31 (อ่านแยกคำ เว้นช่องระหว่างคำนานขึ้น): แทรก token หยุด (`pau` หรือเครื่องหมายวรรคตอนที่ SBV2 รองรับ) ระหว่างคำ ระดับเบาแทรกบางคำ ระดับเข้มแทรกทุกคำ
  - กฎ 29 (ช่วง pitch แคบลง): ใช้พารามิเตอร์ `intonation_scale` ของ SBV2 ที่ค่าน้อยกว่า 1
  - กฎ 32 (ความยาวเท่ากันต่อ mora): ได้มาโดยปริยายจากโมเดลญี่ปุ่น
  - ความเร็วพูดโดยรวม: ใช้ `length`
- **ไม่อยู่ในขอบเขตรอบนี้:** override duration หรือ F0 ราย phoneme (ต้องแก้โค้ดภายในโมเดล) และกฎ 33 (boundary tone)

### 5.3 Mora mapper (การตั้งค่าเริ่มต้นเป็นการตัดสินใจของผม ปรับได้)
- ต้นพยางค์ + สระ → mora ตามชุด phoneme ของ SBV2 JP (เช่น `k a`, `ch i`, `ts u`, `f u`)
- สระยาวที่ไม่ถูกย่อ → เพิ่ม mora ยาว (`:` หรือเทียบเท่า ตามที่ SBV2 ใช้) ตัวสะกดนาสิก → `N` ตัวสะกดหยุด → `q` (ッ) หรือเติมสระ ขึ้นกับระดับสำเนียง
- **การแมปวรรณยุกต์เป็น tone 0/1 (ค่าเริ่มต้น):**
  - สูง (ตรี) → H
  - ต่ำ (เอก) → L
  - กลาง (สามัญ) → ใช้ระดับเดียวกับ mora ก่อนหน้า (เริ่มประโยคด้วย L)
  - ขึ้น (จัตวา) → L ต่อด้วย H ถ้ามี 2 mora ขึ้นไป ถ้ามีแค่ 1 mora ใช้ H
  - ตก (โท) → H ต่อด้วย L ถ้ามี 2 mora ขึ้นไป ถ้ามีแค่ 1 mora ใช้ H
- ทำตารางนี้เป็น config เพราะเป็นตัวแปรหลักที่จะทดลองในขั้นประเมินผล
- **ตารางที่ 2 (สำหรับเปรียบเทียบ) = กฎ 30 + กฎ 25/26 จากรายงาน:**
  - โท → H ต่อด้วย L
  - จัตวาและตรี → L ต่อด้วย H (ตรีถูกรวมกับจัตวา ตามกฎ 25)
  - สามัญและเอก → ระดับเดียว คือ L (เอกถูกยกเป็นสามัญ ตามกฎ 26)
  - ตารางที่ 1 ใช้ตามค่าเริ่มต้นข้างบน ส่วนตารางที่ 2 สะท้อนพฤติกรรมผู้เรียนจริงมากกว่า

### 5.4 ข้อมูลสำหรับเทรน
ผู้ใช้ให้ผมเลือกชุดเสียงเอง เงื่อนไขคือต้องเป็นผู้พูดคนเดียวกันทั้งชุด และเงื่อนไขการใช้ต้องอนุญาตให้เทรนโมเดล

| บทบาท | ชุดเสียง | เหตุผล | เงื่อนไขสำคัญ |
|---|---|---|---|
| **หลัก** | **あみたろの声素材工房 (ITA コーパス อ่านโดยあみたろ / 小春音アミ)** | เสียงสาวน่ารัก ใกล้เคียง VTuber ที่สุดในชุดที่เปิดให้ใช้ มีคนนำไป fine-tune VITS และ SBV2 สำเร็จแล้ว (เช่น VITS ที่ใช้ไฟล์ 76 ไฟล์) | ต้องทำตามเงื่อนไขของ amitaro.net ใส่เครดิตทุกครั้งที่เผยแพร่เสียง ห้ามใช้กับงานจำกัดอายุ ห้ามอ้างว่าเป็นเสียงของあみたろตัวจริง |
| สำรอง / M0 | つくよみちゃんコーパス | มีโมเดล SBV2 ที่คนเทรนไว้แล้ว ใช้ทดสอบ M0 ได้ทันที | ต้องทำตามเงื่อนไขของ corpus เมื่อแก้ไขหรือแจกจ่ายโมเดล |
| ทดลองเพิ่ม (ภายหลัง) | JVNV ผู้พูด F1 หรือ F2 | เสียงมีอารมณ์ รวมถึงอารมณ์ดีใจ เหมาะทดลอง style ร่าเริง | CC BY-SA 4.0 ใช้เป็นการทดลองแยก ห้ามผสมกับชุดหลัก |

- ต้องอ่านเงื่อนไขฉบับเต็มของ amitaro.net อีกครั้งก่อนดาวน์โหลด และบันทึกข้อความเครดิตไว้ในโฟลเดอร์ข้อมูล
- ถ้าผู้ให้เสียงมีชุดอ่านแบบหลายอารมณ์ ให้ใช้เฉพาะชุดปกติกับชุดร่าเริงเป็น style ของ SBV2 (ผู้สร้างตรวจสอบเอง)
- เตรียมข้อมูลตามขั้นตอนของ SBV2 ได้แก่ resample, ตัดเสียงเงียบ, สร้าง `train.list` / `val.list`

### 5.5 การเทรน (Colab)
- ใช้ `colab.ipynb` ทางการของ Style-Bert-VITS2 และ `train_ms_jp_extra.py` เริ่มจาก pretrained `litagin/Style-Bert-VITS2-2.0-base-JP-Extra`
- เก็บ `dataset_root` และ `assets_root` ไว้ใน Google Drive กำหนด save interval ให้ถี่พอ (เช่นทุก 500–1000 step) เพื่อให้ resume ได้หลัง session ถูกตัด
- **การทดลองหลักเรื่อง BERT:** เทรนสองแบบเพื่อเปรียบเทียบ
  - **E1 baseline:** เทรนตามปกติ ใช้ BERT feature จากข้อความญี่ปุ่นจริง
  - **E2 neutral-BERT:** ตอนเทรนแทน BERT feature ด้วยค่าเป็นกลาง (ศูนย์หรือค่าเฉลี่ย) ให้ตรงกับตอนใช้งาน ที่ข้อความไทยไม่มีความหมายในภาษาญี่ปุ่น
  - เปรียบเทียบว่าแบบไหนอ่านภาษาไทยได้ชัดกว่าและเพี้ยนน้อยกว่า

### 5.6 การสังเคราะห์เสียง
- ส่ง phones + tones จากข้อ 5.3 ตรงเข้าโมเดล โดยข้าม g2p ญี่ปุ่นของ SBV2 ถ้า API ของเวอร์ชันที่ใช้รองรับ (เช่นพารามิเตอร์ระดับ phone/tone) ให้ใช้ API นั้น ถ้าไม่รองรับให้เขียน wrapper ที่เรียกโมเดลในระดับ tensor
- BERT input ตอนใช้งานต้องตรงกับแบบที่เทรน (E1 ใช้คาตาคานะ, E2 ใช้ค่าเป็นกลาง)
- ปรับ style และ style weight ของ SBV2 ได้ เพื่อเพิ่มความเป็นสาวน้อย VTuber (สดใส ร่าเริง)

### 5.7 การประเมินผล
- ชุดประโยคทดสอบภาษาไทย 30 ประโยค ครอบคลุมวรรณยุกต์ทั้ง 5 เสียง สระสั้น/ยาว คำควบ และตัวสะกดทุกแบบ
- **ความเข้าใจได้:** CER/WER จาก ASR ภาษาไทย (Whisper large-v3 หรือ Typhoon)
- **ความเป็นธรรมชาติ:** UTMOS
- **การฟังจริง:** ผู้ใช้กับคนไทย 2–3 คน ให้คะแนน 1–5 ทั้งด้านฟังรู้เรื่องและความเป็นสำเนียงญี่ปุ่น
- เปรียบเทียบ ระดับสำเนียง × (E1, E2) × ตารางแมปวรรณยุกต์ 2 แบบ
- บันทึกผลทุกรอบในตารางเดียว เพื่อให้เห็นว่าการเปลี่ยนแปลงแต่ละอย่างส่งผลอย่างไร

## 5.8 Notebook (ผู้ใช้รันเอง ต้องการระดับ best practice และรองรับกรณี GPU หลุด)

ผู้ใช้ยังไม่ได้บอกว่าใช้ Colab แบบฟรีหรือแบบเสียเงิน **จึงออกแบบให้รองรับ Colab ฟรีเป็นค่าเริ่มต้น** (การตัดสินใจของผม)

**แบ่งเป็น notebook ตามขั้นตอน**
- `00_m0_smoke_test.ipynb` – ทดสอบโมเดลที่มีอยู่แล้ว (รันบน CPU ได้)
- `01_data_prep.ipynb` – ดาวน์โหลดข้อมูล, ตรวจ license และเครดิต, resample, ตัดเสียงเงียบ, ตรวจคุณภาพ (ความยาว, clipping, ข้อความตรงกับเสียง), สร้าง `train.list` / `val.list`
- `02_train.ipynb` – fine-tune SBV2 JP-Extra
- `03_infer_thai.ipynb` – ไทย → phone/tone → เสียง
- `04_eval.ipynb` – วัด CER, UTMOS และสร้างไฟล์สำหรับการฟังจริง
- โค้ดหลักอยู่ในแพ็กเกจ Python `thaijp_accent/` (front-end, rules, mora mapper, eval) มี unit test และ notebook ทำหน้าที่เรียกใช้เท่านั้น

**การรองรับ GPU หลุดหรือ session ถูกตัด**
- Drive เป็น source of truth: ข้อมูล, cache ที่ประมวลผลแล้ว, checkpoint, log และ config เก็บใน `MyDrive/thaijp_tts/<run_id>/`
- ทุก cell รันซ้ำได้โดยไม่เกิดผลเสีย (idempotent) ตรวจว่ามีผลลัพธ์อยู่แล้วหรือไม่ก่อนทำซ้ำ และใช้ไฟล์ marker หรือ hash ของข้อมูล
- Auto-resume: `02_train` หา checkpoint ล่าสุดใน Drive แล้วเทรนต่อเองโดยไม่ต้องแก้อะไร
- เขียน checkpoint แบบ atomic (เขียนไฟล์ชั่วคราวก่อนแล้วจึงเปลี่ยนชื่อ) เก็บไว้ N ตัวล่าสุด และเก็บตัวที่ดีที่สุดแยกไว้
- บันทึกตามจำนวน step ไม่ใช่ตาม epoch และมีตัวจับเวลาที่บันทึก checkpoint ก่อนชนเพดานเวลา
- ตรวจ GPU ตอนเริ่ม (`nvidia-smi`) แล้วเลือก batch size และ precision ตาม VRAM ถ้าเกิด OOM ให้ลด batch size ครึ่งหนึ่งแล้วลองใหม่
- ถ้าไม่ได้ GPU ให้หยุดพร้อมข้อความชัดเจน แทนการเทรนบน CPU โดยไม่รู้ตัว
- ก่อนเทรน copy ข้อมูลจาก Drive ไปที่ดิสก์ local ของ Colab เพื่อลด I/O แต่ checkpoint เขียนกลับไปที่ Drive

**ความทำซ้ำได้ (reproducibility)**
- ตรึงเวอร์ชัน (pin) Style-Bert-VITS2 ด้วย git tag และตรึงเวอร์ชันแพ็กเกจหลัก
- กำหนด seed
- ใช้ config เป็นไฟล์ YAML ไฟล์เดียวต่อ run
- บันทึก run manifest (config, commit, hash ของข้อมูล, GPU ที่ได้)

**การติดตามผล**
- ใช้ TensorBoard จาก log ใน Drive
- สร้างเสียงตัวอย่างประโยคไทยชุดเดียวกันทุกครั้งที่บันทึก checkpoint เพื่อฟังพัฒนาการ

**การสอน:** แต่ละขั้นมี markdown อธิบายว่าทำอะไร ทำไม และควรเห็นผลอะไร

## 6. ลำดับงาน (milestones)

- **M0 – ทดลองไม่ต้องเทรน:** ใช้โมเดล SBV2 つくよみちゃん ที่มีคนเทรนไว้แล้วบน Hugging Face ป้อนคาตาคานะภาษาไทยที่ถอดเองด้วยมือ 5 ประโยค เพื่อเช็กว่าแนวคิดนี้ฟังรู้เรื่องจริงก่อนลงแรง
  - **เกณฑ์ผ่าน (การตัดสินใจของผม):** ผู้ใช้กับคนไทยอีก 1–2 คน ฟังแล้วจับใจความได้อย่างน้อย 3 ใน 5 ประโยค โดยไม่ต้องดูข้อความ และ CER จาก ASR ไทยไม่เกิน 40%
  - **ถ้าไม่ผ่าน:** ลองป้อน phone/tone ตรง (ส่วนหนึ่งของ M3) ก่อน ถ้ายังไม่ผ่าน จะหยุดแล้วกลับมาคุยกับผู้ใช้ว่าจะเปลี่ยนไปทาง F5-TTS-THAI + เสียงอ้างอิงหรือไม่ จะไม่เปลี่ยนเอง
- **เกณฑ์จบ M4 (การตัดสินใจของผม):** ระดับเบาได้ CER ไม่เกิน 25% และคะแนนฟังรู้เรื่องเฉลี่ย ≥ 3.5/5 หรือครบ 3 รอบของการปรับแล้วเทรนซ้ำ ขึ้นกับว่าอย่างไหนมาถึงก่อน
- **M1:** front-end + rule engine + mora mapper พร้อม unit test (ทำงานบน CPU ได้)
- **M2:** เตรียมข้อมูลและ fine-tune แบบ E1 บน Colab ให้ resume ได้
- **M3:** เชื่อม inference แบบป้อน phone/tone ตรง และทำการทดลอง E2
- **M4:** ประเมินผลและสรุปเป็นตาราง
